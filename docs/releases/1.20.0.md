# LLM Monitor 1.20.0

[English](#english) · [简体中文](#简体中文)

## English

A consolidation release. Quota colors now follow one time-aware rule across every surface, the
status bar center follows whichever plan is still serving you, local-usage scanning gains
bounded recovery instead of silent data loss, and two crash-class defects are gone.

### Highlights

- **One time-aware color rule everywhere**: the status bar and the provider cards share a single
  `colorLevel` threshold — under 15% is red; a short 5-hour window turns yellow below 30%; a long
  window (≥24h) uses `min(time remaining, 50)`, so the yellow line tightens as the reset
  approaches. The SF Symbol status dot, the Icon Duo center, the Icon Duo bottom dots, and the
  card header dot all now agree. Concrete shifts: 35% remaining on a 5-hour window is now green
  (was yellow), 15% is now yellow (was red).
- **The center sector follows the plan in service**: it shows the lowest "actually available"
  ratio across plans (`min(5-hour remaining, weekly remaining × weekly multiplier)`), and a
  plan that is fully used up drops out of that comparison instead of dragging the ring to zero.
  When you roll from one plan to the next, the ring tracks the one still serving you. When every
  plan is exhausted the ring correctly reads zero (red); when no plan is configured it stays
  gray. The three plan health dots at the bottom still show every plan, so a spent plan stays red.
- **Recovery action for local usage**: Settings → Antigravity gains a "Force full rebuild of
  local cache" button. It re-requests trajectory metadata for every session, ignoring the cache,
  for when the numbers look wrong. It respects the global refresh lock and reports honestly if it
  was cancelled or preempted.
- **Local usage caches moved to one app-owned directory**: all five scanners now keep a single
  `<provider>.json` under `~/Library/Application Support/LLM-monitor/token-monitor/`. The first
  run after upgrading rebuilds from the clients' own data (your original databases are never
  touched); old directories are left in place.
- **Budget-truncated usage now says so**: when a scan hits its per-round file/byte budget, both
  the Settings client row and the 7-day chart hover show an orange note that the oldest sessions
  were left out, instead of presenting a partial figure as complete.
- **Smaller package**: the bundled app icon is downsampled to 256px and release builds use
  `-Osize`. The app shrinks from 5.9MB to 4.7MB (DMG 4.1MB → 3.3MB).
- **Stability fixes**, including two crash-class defects: a corrupted Antigravity step-timestamp
  blob could trap the whole process while parsing (now rejected safely), and a file-watcher
  callback bypassed actor isolation, risking a crash on stop/start cycles. Also: manual refresh
  of one card no longer shifts every other provider's schedule or their periodic-full counter;
  system wake-ups coalesce instead of firing an extra full refresh per provider; a cancelled
  Codex refresh no longer discards cached reset credits; a failing sleep-assertion probe reports
  "unknown" instead of a false green; Antigravity IDE process matching is anchored so a
  workspace path containing the substring no longer hides a working process; notification
  cooldowns are no longer burned while notifications are unauthorized; a truncated server
  response no longer silently overwrites local history; and the HTTP response size limit is now
  actually enforced (it previously never ran).

### Install

Download `LLM-monitor-1.20.0.dmg` from the release assets, drag **LLM-monitor.app** into
**Applications**, and verify the SHA-256 checksum against `SHA256SUMS.txt`. The build is ad-hoc
signed; right-click → Open on first launch if Gatekeeper asks.

## 简体中文

整合版本：额度红黄绿判定统一为一套时间感知规则，状态栏中心跟随仍在服役的套餐，本地用量
扫描补上有界恢复而不再静默丢数据，并修掉两处崩溃级缺陷。

### 主要更新

- **红黄绿判定全界面统一**：状态栏与 Provider 卡片共用同一套 `colorLevel` 阈值——低于 15% 判红；
  5 小时短窗口低于 30% 判黄；24h 以上长窗口用 `min(剩余时间%, 50)`，越接近重置黄线越紧。SF Symbol
  状态圆点、Icon Duo 中心扇形、Icon Duo 底部三点、卡片头部点现在口径一致。行为变化示例：5 小时
  剩余 35% 由黄转绿，15% 由红转黄。
- **中心扇形跟随在服役的套餐**：显示各套餐「实际可用」（`min(5 小时剩余, 周剩余 × 周倍率)`）的
  最低值，且已完全用完的套餐不再参与比较、不再把环拖到 0。从一个套餐接力到下一个时，中心跟随
  仍在服役的那个；全部套餐耗尽时中心如实显示 0（红）；没有任何套餐时保持灰色。底部三个套餐健康点
  仍逐个展示，用完的套餐点保持红色。
- **本地用量的恢复入口**：设置页 Antigravity 区新增「强制全量重建本地缓存」按钮，忽略缓存对所有
  session 强制重新请求 trajectory metadata，用于数据看起来不对时的恢复。该操作遵循全局刷新锁，
  被取消或被占用时如实反馈。
- **本地用量缓存集中到统一目录**：五个 scanner 现在各自在
  `~/Library/Application Support/LLM-monitor/token-monitor/` 下维护一个 `<provider>.json`。升级后首次
  运行会从客户端原始数据冷重建（客户端自己的数据库不会被改动），旧目录原地保留。
- **预算截断如实提示**：单轮扫描触及文件数/字节预算时，设置页客户端行与 7 天柱图悬浮明细都会给出
  橙色提示说明最旧 session 未计入，不再把不完整的数字当作完整用量展示。
- **安装包更小**：打包图标降采样到 256px，release 构建启用 `-Osize`。App 包 5.9MB → 4.7MB
  （DMG 4.1MB → 3.3MB）。
- **稳定性修复**，含两处崩溃级缺陷：Antigravity 步级时间戳的损坏 blob 此前会在解析时 trap 整个
  进程（现安全拒绝）；文件监听回调此前绕过 actor 隔离，stop/start 周期下有崩溃风险。此外：手动刷新
  单张卡片不再打乱其他 provider 的排期与周期 full 计数；系统唤醒改为合并窗口，不再对每个 provider
  多发一次 full；Codex 刷新被取消不再误清已缓存的 reset credits；睡眠断言探针失败按「未知」处理而
  不再产出假绿；Antigravity IDE 进程识别改为锚定匹配，工作区路径含该子串不再误隐藏可用进程；未授权
  期间不再白烧通知冷却；服务端截断响应不再静默覆盖本地历史；HTTP 响应体上限此前从未真正生效，现已
  实际执行。

### 安装

从 Release 附件下载 `LLM-monitor-1.20.0.dmg`，将 **LLM-monitor.app** 拖入 **Applications**，并核对
`SHA256SUMS.txt` 中的 SHA-256。安装包为 ad-hoc 签名，首次打开如遇 Gatekeeper 拦截，请右键 →「打开」。
