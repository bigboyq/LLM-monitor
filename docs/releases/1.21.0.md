# LLM Monitor 1.21.0

[English](#english) · [简体中文](#简体中文)

## English

A dual-perspective release: the **menu bar dropdown becomes a Harness (client) view** of today's
local token usage, while the **hover cards gain a quota-window usage block** that shows how much
of the current 5h/weekly quota cycle the machine actually burned. Under the hood, Provider ×
Harness accounting converges into a single projection kernel driven by the client-binding matrix.

### Highlights

- **Menu = Harness view**: the dropdown now opens with a global today summary (total tokens ·
  cache hit rate · total value + a three-bucket ratio bar), followed by one section per client
  (ZCode, Antigravity, Codex, OpenCode, DSH, MiniMax Code — sorted by today's tokens, idle
  clients hidden). Each model gets a row: name + colored input/cache-read/output bar + token
  count + hit rate + nominal value in its own currency. Mixed-currency subtotals fold into CNY
  at USD ×7 and render as `10.5（含$1.3）` — total 10.5 = ¥1.4 + $1.3×7, with the USD original
  kept in the parens. A **Provider status strip** at the bottom shows enabled providers as
  compact pills (keeping the worst-health ones when space runs out); hovering one pops the full
  provider card, so quota info stays reachable without the edge dock. Freshness badge, truncation
  notices, and right-click refresh/open-config on section headers included.
- **Quota-window usage block** (on hover cards, between the quota section and local usage): a
  time-share bar where the full track is the local token total of the current weekly window,
  the solid left segment is the most recent 5-hour window's share, and the translucent remainder
  is everything older — one glance tells whether you're in a burst or on the long tail. Below it,
  one line per window with five metrics: `5h 173M · hit 97.8% · out/in 12% · thinking 41% ·
  ¥12.34` (token total, cache hit = cached/(input+cached), out/in = (reason+output)/(input+cached),
  thinking share = reason/(reason+output), nominal value in the original currency; `—` when a
  denominator is zero; labels auto-compress instead of wrapping). The block expands in place to
  the two windows' four-bucket absolutes and reset times, and the **per-card reset-credit list
  (count + date each) lives here too** — it was previously unreachable because both hosts sit in
  mouse-transparent panels. GLM off-peak tasks stay excluded, matching the quota-window
  accounting; balance-type providers (DeepSeek) show no block.
- **Edge dock**: the collapsed mini-ring size is now configurable (S 21 / M 31 / L 38pt edge
  thickness, default S = previous look), and the dual rings take **independent colors** (outer =
  5h window, inner = weekly, each by its own time-aware thresholds on the tightest model; inner
  ring is now thinner for structural distinction). This fixes a pre-existing mismatch where
  ring lengths were per-window but the color was a single provider-level health.
- **Internals**: a unified `UsageProjectionKernel` absorbs the old DSH/OpenCode mergers and the
  contribution factories; client ↔ provider attribution is now driven solely by the
  `clientBindings` matrix in config.json (the two derived merge booleans are gone; DSH gains
  three default-on bindings matching the previous routing, and unmatched provider keys log a
  warning instead of silently dropping usage). Raw→bucket conversion funnels through
  `TokenAccountingCatalog` as the single entry point, and peak-hour pricing became a registry.

### Install

Download `LLM-monitor-1.21.0.dmg` from the release assets, drag **LLM-monitor.app** into
**Applications**, and verify the SHA-256 checksum against `SHA256SUMS.txt`. The build is ad-hoc
signed; right-click → Open on first launch if Gatekeeper asks.

## 简体中文

双视角版本：**状态栏下拉改为 Harness（客户端）视角**看今日本地 token 用量，**悬浮卡新增额度窗口
用量区块**看这一轮 5h/周额度里本机实际烧了多少；底层 Provider × Harness 记账收敛为绑定矩阵驱动的
单一投影内核。

### 主要更新

- **菜单 = Harness 视角**：下拉顶部是全局今日汇总（合计 tokens · 命中率 · 总价值 + 三桶占比条），
  下面按客户端分段（ZCode / Antigravity / Codex / OpenCode / DSH / MiniMax Code，今日 token 降序，
  无活动的不出现），每个模型一行：名称 + input/缓存/output 三色条 + token 数 + 命中率 + 原币种名义
  价值。段小计与总价值遇混币按 USD ×7 统一折算 CNY，展示 `10.5（含$1.3）`：总额 10.5 = ¥1.4 +
  $1.3×7，括号保留美元原额。底部「**Provider 状态**」兜底行横排已启用 Provider 的状态胶囊（放不下
  保留健康最差并显示 +N），悬停弹出完整 Provider 卡片——不开边缘窗也随时能查额度。另有新鲜度胶囊、
  截断单行提示（悬停看全文）、段头右键「立即刷新全部 / 打开配置文件」。
- **额度窗口用量区块**（悬浮卡，额度区与本地用量之间）：时间构成条——满条为当前周额度窗口内实际
  发生的本地 token 总量，左段实色为最近 5h 窗口的量，右段半透明为 5h 之外的量，一眼看出是在爆发期
  还是长尾期。下面每个窗口一行五个指标：`5h 173M · 命中 97.8% · 出/入 12% · 思考 41% · ¥12.34`
  （命中率 = cached/(input+cached)、出/入 = (reason+output)/(input+cached)、思考 = reason/(reason+output)、
  价值原币种；分母为 0 显示 `—`，宽度不够自动压缩标签不换行）。区块就地展开两窗口的四桶绝对值与
  重置时刻，**重置卡的逐张明细（每张数量与日期）也并入此处**——此前两个宿主浮层都不接收鼠标事件，
  明细等于不可达。口径与额度窗口统计同源（GLM 闲时排除），余额型（DeepSeek）不显示该区块。
- **边缘状态窗**：收起小圆环尺寸三档可配（小 21 / 中 31 / 大 38pt 贴边，默认小=原状）；双环**独立
  取色**（外环 5h、内环周，各按自己的时间感知阈值取最吃紧 model 的档位，内环加细做结构区分）——
  修复了环长分窗口而颜色统一的既有口径矛盾。
- **内部**：`UsageProjectionKernel` 统一投影内核吸收旧 DSH/OpenCode Merger 与贡献工厂；客户端 ↔
  Provider 归因只由 config.json 的 `clientBindings` 矩阵驱动（两个派生 merge 布尔删除，DSH 新增
  三条默认开启绑定与旧路由行为一致，未认领 provider 键打日志告警不再静默漏采）；raw→桶转换收口
  `TokenAccountingCatalog` 单一入口，峰时倍率改登记表。

### 安装

从 Release 附件下载 `LLM-monitor-1.21.0.dmg`，将 **LLM-monitor.app** 拖入 **Applications**，
并核对 `SHA256SUMS.txt` 中的 SHA-256。安装包为 ad-hoc 签名，首次打开如遇 Gatekeeper 拦截，
请右键 →「打开」。
