# LLM Monitor 1.23.2

[English](#english) · [简体中文](#简体中文)

## English

A patch release with three fixes and two small features: card countdowns no longer freeze
inside the hover panels, peak-hour rules now exclude statutory holidays, and the GLM peak
window is no longer configurable — it follows the official rule, shown read-only.

### Fixed

- **Frozen countdowns in provider cards**: the peak-hour countdown and the freshness
  capsule read the shared display clock from the environment, but the two hosts that
  actually render a card — the menu strip's hover panel and the edge dock's popover —
  never injected it, so they fell back to the environment key's static default value: a
  `Date()` evaluated once per process. The countdown therefore stayed frozen at the
  moment of the first render (a DeepSeek card stuck at 「距高峰 1分」 — the symptom of a
  peak boundary already in the past; present since 1.8.0). Both hosts now own a display
  clock that starts/stops with the panel. The same pass routes the quota-window reset
  countdown, the reset-credit remaining time and staleness check, and the card's "today"
  boundary through the same clock — and a new source-scanning guard test fails the suite
  if a card-rendering host ships without the injection.
- **Settings copy**: the GLM peak section said the window follows the machine's local
  timezone — it is Beijing time (see below).

### Added

- **Statutory holidays are not peak hours** — Rule A: a working day is Mon–Fri *and* not
  a statutory holiday. A bundled China holiday snapshot (2025–2026, generated by
  `scripts/sync-holiday-data.sh` from the [chinese-days](https://github.com/vsme/chinese-days)
  dataset) drives the rule for both providers. 调休 holidays that land on weekdays are
  excluded; weekend makeup workdays are non-peak by definition. The next-peak scan budget
  was widened from 8 to 15 days so long breaks (Spring Festival, National Day) resolve to
  the first working day after the holiday.
- **Configurable holiday data source** (Settings → General): defaults to the upstream
  `chinese-days` JSON; an explicit empty string means "bundled snapshot only, never
  fetch"; otherwise a URL or local file path. Fetches are best-effort with a local cache
  (`holidays-cache.json`, 7-day freshness window) and a 「立即更新」 button — a failed
  refresh never discards the table in use.

### Changed

- **GLM peak window de-configured** — fixed to the official Mon–Fri 14:00–18:00 (Beijing
  time, statutory holidays excluded) and displayed read-only in Settings.
  `peakStartHour` / `peakEndHour` / `peakWeekdaysOnly` are gone from `config.json`;
  residual keys in old configs are ignored silently. GLM and DeepSeek now share one
  shape: same rule, same timezone — only the number of time slots differs.
- **Everything is Beijing time** — both providers judge peak windows against
  Asia/Shanghai regardless of the machine's timezone (GLM previously used the local
  timezone).

### Install

Download `LLM-monitor-1.23.2.dmg` from the release assets, drag **LLM-monitor.app** into
**Applications**, and verify the SHA-256 checksum against `SHA256SUMS.txt`. The build is ad-hoc
signed; right-click → Open on first launch if Gatekeeper asks.

## 简体中文

补丁版本，含三个修复与两个小功能：卡片倒计时不再在浮层里冻结、高峰判定排除法定节假日、
GLM 高峰窗口改固定口径（设置页只读）。

### 修复

- **卡片倒计时在浮层里永久冻结**：高峰倒计时与新鲜度胶囊读的是环境里的共享展示时钟，
  而实际渲染卡片的两个宿主——菜单兜底行的 hover 浮层与边缘状态窗的悬停浮层——从未注入
  它，于是落到环境键的 `static let` 兜底值（进程内只求值一次）：倒计时永远停在首次渲染
  那一刻（DeepSeek 卡恒显「距高峰 1分」——边界时刻落在过去后的负差钳位症状；1.8.0 起存在）。
  两个宿主现各自持有随面板显隐 start/stop 的展示时钟。同一轮把额度窗口「重置日期」倒计时、
  重置卡剩余时间与过期判定、卡内「今天」边界一并接到同一时钟，并新增源码扫描护栏测试——
  今后任何渲染卡片的宿主漏注入，测试会直接红。
- **设置页文案**：GLM 高峰段原写「按本机时区计算」，实际为北京时间（见下）。

### 新增

- **法定节假日不计高峰**——Rule A：工作日 = 周一–周五**且**当天不是法定节假日。随包携带
  中国法定节假日快照（2025–2026，由 `scripts/sync-holiday-data.sh` 自
  [chinese-days](https://github.com/vsme/chinese-days) 数据生成），两家 Provider 共用同一规则：
  调休换来的放假日（常落在周一–周五）会排除；调休上班的周六/周日按定义不算高峰。next-peak
  扫描窗口由 8 天放宽到 15 天，春节、国庆等长假后的倒计时能正确指向假期后第一个工作日。
- **节假日数据源可配置**（设置 → 通用）：缺省用上游 chinese-days JSON；显式空串 = 只用内置
  快照、不联网；也可填 URL 或本地文件路径。取数为 best-effort，带本地缓存
  （`holidays-cache.json`，7 天新鲜度窗口）与「立即更新」按钮——刷新失败绝不会丢弃在用的表。

### 变更

- **GLM 高峰窗口去配置化**——固定官方口径（北京时间周一–周五 14:00–18:00，法定节假日除外），
  设置页只读展示。`config.json` 的 `peakStartHour` / `peakEndHour` / `peakWeekdaysOnly` 已移除，
  旧配置里的残留键静默忽略。GLM 与 DeepSeek 从此同一判定形状：同规则、同时区，只差时间段数量。
- **全 app 统一北京时间**：两家 Provider 的高峰判定一律锚定 Asia/Shanghai，与本机时区无关
  （GLM 此前用本机时区）。

### 安装

从 Release 附件下载 `LLM-monitor-1.23.2.dmg`，将 **LLM-monitor.app** 拖入 **Applications**，
并核对 `SHA256SUMS.txt` 中的 SHA-256。安装包为 ad-hoc 签名，首次打开如遇 Gatekeeper 拦截，
请右键 →「打开」。
