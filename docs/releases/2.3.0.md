# LLM Monitor 2.3.0

[English](#english) · [简体中文](#简体中文)

## English

This release separates normal quota refreshes from less frequent secondary information, automatically attributes supported local usage, improves GLM campaign recognition, and groups Settings usage by quota pool.

### Refresh frequency controls

- The General settings pane now has a default refresh interval for main quota and balance data, plus a 1–30× secondary-information slider (default 20×).
- The secondary interval covers reset cards and independent account, plan, and organization lookups. Estimates use each provider's effective refresh interval, including a provider-specific override when present.
- ChatGPT, Antigravity, and GLM credential settings show their own estimated secondary-information period.

### Automatic local usage attribution

- Supported OpenCode, ZCode, and DSH usage is routed to quota cards by the provider recorded in each local ledger. There is no user-facing attribution switch.
- Legacy `clientBindings` and `mergeOpencodeUsage` values no longer control attribution. Unknown provider IDs are left unattributed rather than guessed, and each quota provider's own enable/disable setting remains independent.

### GLM campaign banners

- GLM credential mode recognizes claimable plans from the ZCode campaign banner, including the campaign ID, plan details, and claim action. A post-claim success popup is not mistaken for a new claimable activity.
- ZCode credential paths accept `～` or `˜` at the start as a home-directory `~`; characters inside a path are preserved.

### Usage grouped by quota pool

- Settings → Usage classifies harness samples by quota pool, retaining ZCode's Coding/Start categories and splitting Antigravity, Agy, and OpenCode usage attributed to Antigravity into Gemini, Claude/GPT, and Argon groups.
- Unmatched samples and daily-bucket differences remain separately unassigned; authoritative totals are preserved. A pool's 5-hour and weekly windows are one group, not two.
- This grouping applies to the Settings usage view; menu and Fleet views are unchanged.

## 简体中文

本版本将主额度刷新与次要信息查询分开调节，为支持的本地用量来源自动归因，改进 GLM 活动识别，并在设置页按额度池分类显示用量。

### 刷新频率设置

- 「常规」设置页新增默认刷新频率，用于主额度与余额；次要信息频率改为 1～30 倍滑块，默认 20 倍。
- 次要频率控制重置卡及独立的账号、套餐、组织信息查询。预计周期按 Provider 的有效刷新间隔计算，存在独立间隔时优先使用独立间隔。
- ChatGPT、Antigravity 和 GLM 凭证模式的设置页会显示各自的预计次要信息周期。

### 本地用量自动归因

- 已支持的 OpenCode、ZCode、DSH 用量按本地账本记录的 provider 自动归入对应额度卡，不再提供用户归因开关。
- 历史 `clientBindings` 和 `mergeOpencodeUsage` 值不再控制归因。无法识别的 provider 不会被猜测归类；各 Provider 自身的启用/停用设置保持独立。

### GLM 活动 banner

- GLM 凭证模式可识别 ZCode 活动 banner 中的活动 ID、套餐信息与领取操作，生成待领取活动提醒；领取后的成功弹窗不会被误认成新活动。
- ZCode 凭证路径开头误输入的 `～` 或 `˜` 会按主目录 `~` 处理，路径中段字符保持原样。

### 用量按额度池分类

- 设置 → 用量按 Harness 额度池分类，保留 ZCode 的 Coding/Start 等分类，并将 Antigravity、Agy 及归入 Antigravity 的 OpenCode 用量拆为 Gemini、Claude/GPT 与 Argon 三组。
- 无法归类的样本与日桶差额保持独立未归属，不改变权威总量。同一额度池中的 5 小时与周窗口只算一组，不会重复分组。
- 此分类只用于设置页「用量」视图；菜单与 Fleet 视图不变。
