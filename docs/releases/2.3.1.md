# LLM Monitor 2.3.1

[English](#english) · [简体中文](#简体中文)

## English

This release makes GLM quota authentication explicit, adds an independent ZCode JWT extension switch, and removes a repeated notification hint from Settings.

### GLM Coding Plan authentication

- A Coding Plan API key is now required to fetch standard quota. The app no longer tries a ZCode OAuth token when the key is missing or rejected.
- ZCode JWT features now have a separate switch, off by default. When enabled, the app reads the configured ZCode credential path and uses the ZCode JWT with the configured API key to access activity-plan balances, reset cards, and campaign details.
- If the switch is off, the app does not read ZCode credentials, call the extension APIs, or display cached ZCode package data. If it is on but no JWT is available, the standard quota request continues and the extension calls are skipped.
- Existing configurations preserve their previous ZCode credential feature setting when the new switch is absent. An explicit value for the new switch takes precedence.

### Settings

- Removed the repeated “campaign notifications must be enabled” hint from the GLM refresh section. Campaign polling still requires the notification channel to be enabled.

## 简体中文

本版本明确 GLM 额度认证方式，新增独立的 ZCode JWT 扩展开关，并移除设置页中重复的活动通知提示。

### GLM Coding Plan 认证

- 查询标准额度现在必须填写 Coding Plan API Key。缺少或 API Key 被拒绝时，不再尝试使用 ZCode OAuth token。
- ZCode JWT 功能改由独立开关控制，默认关闭。开启后，应用读取指定的 ZCode 凭证路径，并使用 ZCode JWT 与已配置的 API Key 查询活动套餐余额、重置卡和营销活动详情。
- 关闭开关时，应用不读取 ZCode 凭证、不调用扩展接口，也不显示缓存的 ZCode 套餐数据。开启但没有可用 JWT 时，标准额度请求仍继续，扩展接口跳过。
- 旧配置未设置新开关时，沿用原有 ZCode 凭据功能的启停状态；若新开关有显式值，则以新值为准。

### 设置

- 移除 GLM 刷新设置区重复的“运营活动需开启通知”提示。活动轮询仍要求启用对应通知渠道。
