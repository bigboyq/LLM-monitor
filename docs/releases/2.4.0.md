# LLM Monitor 2.4.0

[English](#english) · [简体中文](#简体中文)

## English

This release retires the Antigravity local RPC entirely: quota now comes from a login Keychain credential plus the Google Cloud Code endpoint, and local usage is read straight from the session SQLite databases. Antigravity and `agy` no longer need to be running for either quota or local usage.

### Remote quota via Keychain credential

- Quota and account info read the login Keychain entry (`gemini` / `antigravity`) and call the Google Cloud Code quota endpoint directly, so refreshes keep working while Antigravity / `agy` are not running. Tokens are renewed by the Antigravity client inside the Keychain; when the card says the token has expired, open Antigravity to refresh the credential.
- The first credential read triggers one Keychain authorization prompt — choose "Always Allow" and it will not ask again.
- The Antigravity default refresh interval is now 300 seconds, aligned with the IDE's own remote polling cadence.
- New `allowTokenRefresh` provider field: only `false` is accepted (the monitor never refreshes tokens itself). Setting it to `true` in `config.json` is treated as an invalid configuration and follows the config-decode error path; the settings toggle is always off and disabled.

### Local usage read from session databases

- Per-call tokens, models, timestamps and turns now come directly from the session SQLite databases (`gen_metadata` joined with `steps`) under `~/.gemini/antigravity/conversations/` — no network requests and no dependency on running processes.
- Local RPC, process discovery, and `.pb` session support are retired.
- The token-usage cache index moves to v9 with a full rebuild: **the previous 7-day history is cleared once and re-scanned after upgrading, and turns are now counted directly (`step_type=14`) instead of inferred from step-index gaps, so turn counts drop to the corrected values.** This is expected behavior.

### Test stability

- Fixed the chunked-cap handshake timing in HTTP client tests (a latch now waits for the real "client aborted on cap" event) and FleetSync test port selection (kernel-reserved ephemeral ports, fixed sleeps replaced with real-state waits). Test infrastructure only; no runtime behavior change.

## 简体中文

本版本全面退役 Antigravity 本地 RPC：额度改走登录钥匙串凭据 + Google Cloud Code 远端接口，本地用量直读会话 SQLite 数据库。额度与本地用量都不再要求 Antigravity / `agy` 处于运行状态。

### 钥匙串凭据 + 远端额度

- 额度与账号信息改读登录钥匙串条目（`gemini` / `antigravity`）并直接请求 Google Cloud Code 配额接口，Antigravity / `agy` 未运行时刷新照常工作。token 由 Antigravity 客户端在钥匙串内自行续期；卡片提示「token 已过期」时，打开 Antigravity 更新凭据即可恢复。
- 首次读取凭据会弹一次钥匙串授权，点「始终允许」后不再打扰。
- Antigravity 默认刷新间隔提升到 300 秒，对齐 IDE 自身的远端轮询节奏。
- 新增 `allowTokenRefresh` Provider 字段：当前仅接受 `false`（监控侧不做 token 刷新）。在 `config.json` 手改为 `true` 视为无效配置并走配置解码错误路径；设置界面开关恒为关且禁用。

### 本地用量直读会话数据库

- 逐调用 token、模型、时间戳与轮次改由 `~/.gemini/antigravity/conversations/` 下的会话 SQLite 直读（`gen_metadata` 与 `steps` 连接）——不发网络请求、不依赖进程运行。
- 本地 RPC、进程发现与 `.pb` 会话支持退役。
- token 缓存索引升级到 v9 并全新重建：**升级后旧的 7 日历史用量会一次性清零重扫**，且 turns 改为按 `step_type=14` 直计（取代 step-index 间隙推断），数字会回落到修正后的口径。属预期现象。

### 测试稳定性

- 修复 HTTP 客户端测试 chunked-cap 的握手时序（门闩等待「客户端已因超限中止」真实事件）与 FleetSync 测试的端口选择（内核预留临时端口，固定 sleep 换真实状态等待）。仅影响测试基建，不改变运行时行为。
