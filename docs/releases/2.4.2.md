## English

### Local fallback for the stale-Keychain window

- The Keychain entry (`gemini` / `antigravity`) is only written at login / agy usage; tokens refreshed while the IDE runs live in its process memory, so the Keychain copy goes stale. When the credential is expired (or the remote quota endpoint returns 401) while Antigravity is running, quota is now fetched from the local `language_server` RPC instead: the fetcher discovers the running IDE / agy CLI backend (pgrep + listening port + CSRF) and calls `RetrieveUserQuotaSummary` locally. Account email and tier come from the local `GetUserStatus` on full refreshes. The remote path resumes automatically once re-login refreshes the Keychain credential.
- The token-expired message now reads "token 已过期：打开 Antigravity 可继续监控额度，重新登录可刷新凭据" — opening Antigravity restores the local fallback's data source, and re-login refreshes the Keychain credential. The export script message matches (the script stays remote-only, no local fallback).

## 简体中文

### keychain 陈旧窗口的本地回退

- 钥匙串条目（`gemini` / `antigravity`）只在登录 / agy 使用时被写；IDE 运行期间刷新的 token 只在其进程内存，keychain 副本会陈旧。凭据过期（或远端配额接口返回 401）而 Antigravity 正在运行时，额度改读本机 `language_server` RPC：自动发现运行中的 IDE / agy CLI 后端（pgrep + 监听端口 + CSRF）并本地调用 `RetrieveUserQuotaSummary`；完整刷新时账号邮箱与套餐来自本地 `GetUserStatus`。重新登录刷新钥匙串凭据后自动回到远端路径。
- token 过期提示更新为「token 已过期：打开 Antigravity 可继续监控额度，重新登录可刷新凭据」——打开 Antigravity 即恢复本地回退的数据来源，重新登录可刷新钥匙串凭据。`export-antigravity-quota.sh` 的过期提示同步（脚本保持纯远端直连，不做本地回退）。
