# LLM Monitor 2.5.0

[English](#english) · [简体中文](#简体中文)

## English

### Antigravity credential strategy rework (local service first + agy proxy refresh)

- **Local language_server is now the primary quota path**: every refresh first probes the locally running Antigravity backend (millisecond-level process discovery, no Keychain access). While the IDE runs, quota data comes from the local service's in-memory bridge credentials and no longer depends on Keychain freshness. Only when no local backend is available does the monitor fall back to the Keychain credential → Google Cloud Code API path, and the read credential is cached in process memory (fresh tokens are reused across ticks without touching the Keychain).
- **agy proxy refresh**: when the token is expired/missing (or the remote API returns 401) and the "允许监控刷新 Token" toggle is enabled, the monitor runs the locally installed `agy` CLI (`agy models`; PATH or `~/.local/bin/agy`, 30s timeout, mutually exclusive, output never logged) to refresh the Keychain credential via agy's own auth flow, then retries the remote API. Failures back off for one refresh interval; `invalid_grant` failures ask you to sign in again. The expired-token message is now "无法获取 Antigravity 额度：打开 Antigravity 可继续监控额度，重新登录可刷新凭据，或在终端运行 agy models 手动刷新".
- **Toggle semantics flip**: `allowTokenRefresh` is now a real switch (default on) instead of a permanently-disabled control that rejected `true` as invalid config; a new `accessTokenFallback` switch (default on) controls the Keychain → remote fallback path. Both toggles are interactive in the Antigravity settings pane; the read-only "额度来源" (quota source) row stays, with refreshed copy.
- **Startup preflight**: run once at monitor launch and on every config hot-reload. If Keychain access is denied, the fallback toggle is auto-disabled at runtime (shown as off + disabled + "钥匙串访问被拒"; the user's config file is never rewritten). If the agy CLI is not found, the refresh toggle is auto-disabled ("未找到 agy CLI"). A missing Keychain entry (not signed in) is a soft-unavailable state — the toggle stays interactive and recovers automatically after login. Once the cause is resolved, re-enabling the toggle or restarting the app re-runs the preflight.

## 简体中文

### Antigravity 额度凭据策略重构（本地服务优先 + agy 代理刷新）

- **本地 language_server 升格为额度主路径**：每次刷新先探测本机运行中的 Antigravity 后端（毫秒级进程发现、不读钥匙串）——IDE 运行期间额度数据来自本地服务的内存 bridge 凭据，不再依赖钥匙串新鲜度；本地服务不可用时才走钥匙串凭据 → Google Cloud Code 接口兜底，读到的凭据缓存在进程内存（未过期下一拍直接复用，不再重复访问钥匙串）。
- **agy 代理刷新**：token 过期/缺失（或远端 401）时，若「允许监控刷新 Token」开关开启且本机装有 agy CLI（PATH 或 `~/.local/bin/agy`），自动运行 `agy models`（30s 超时、互斥、输出不落日志）触发 agy 自己的认证流刷新钥匙串凭据，随后重试远端；失败退避一个刷新周期，`invalid_grant` 类失败提示重新登录。过期提示更新为「无法获取 Antigravity 额度：打开 Antigravity 可继续监控额度，重新登录可刷新凭据，或在终端运行 agy models 手动刷新」。
- **开关语义翻正**：`allowTokenRefresh` 从「恒为关、true 视为无效配置」翻正为真开关（缺省开启）；新增 `accessTokenFallback` 开关（缺省开启）控制钥匙串 → 远端兜底路径。两枚开关在设置页真实可交互；「额度来源」只读行保留并更新文案。
- **启动预检**：monitor 启动与配置热重载时各执行一次——钥匙串授权被拒时自动关闭「钥匙串额度兜底」（设置页显示 off + disabled + 「钥匙串访问被拒」，不改用户 json）；未找到 agy CLI 时自动关闭「允许监控刷新 Token」（显示「未找到 agy CLI」）；钥匙串条目不存在（未登录）为软不可用，开关保持可交互，登录后自动恢复。原因消除后手动重开开关或重启应用即触发重新预检。
