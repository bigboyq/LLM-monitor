# LLM Monitor 2.5.5

[English](#english) · [简体中文](#简体中文)

## English

### Changed

- **ZCode GLM card: Method A retired, unified char-proportion reasoning split.** On-device verification showed the native `reasoning_tokens` column has zero populated rows, every thinking call also carries visible text parts (2019/2019 sampled), and `output_tokens` includes reasoning (hypothesis test: 2.06 chars/token baseline vs 2.43 with-thinking vs 1.44 text-only). The old whole-round classification zeroed visible output for all of them. The GLM card now uses the same three-stage split as the non-zhipu slices (native column passthrough → part char share via `ReasoningCharSplit`, day-level for daily and row-level for samples, conservative). Cache v12 → v13.
- **agy: native reasoning tokens from gen_metadata `f1.f4`.** The conversation dbs carry exact usage (f3 rawOutput = f9 reasoning + f10 normalized; measured 100% conservation across 10 dbs, 267/267 rows 1:1 by step index, totals exactly equal to the transcript's). When the per-call conservation check against the transcript passes, the exact native split replaces the char estimate; anything else falls back to the previous char split. Cache v4 → v5.
- **MiniMax Code: call-level reasoning split.** The FIFO duration pairing (already 100% matched) now also carries each message's `thinking_content` / `msg_content` chars, so paired calls split by their own char share instead of the day-wide average; daily buckets sum the call-level results with a char-based residual for unpaired remainder (day-level behavior kept as fallback when a day has no pairing). Cache v18 → v19.

### Fixed

- MiniMax duration query no longer throws on rows with malformed `data_json` plus a non-null turn id (now wrapped in `json_valid` like the other queries).

## 简体中文

### 变更

- **ZCode GLM 卡：废止 Method A，统一字符分摊。** 实测原生 `reasoning_tokens` 列 0 行有值、思考调用 100%（2019/2019 抽样）同时含可见 text 块、`output_tokens` 包含思考（基准 2.06 chars/token vs 含思考 2.43 vs 仅正文 1.44）——旧的整轮硬分类把可见输出全部清零。GLM 主卡现与非智谱分片同一套三段式（native 列透传 → `ReasoningCharSplit` part 字符比例；daily 日级、samples 行级，守恒）。缓存 v12 → v13。
- **agy：gen_metadata `f1.f4` 原生真值拆分。** 会话库自带精确 usage（f3 rawOutput = f9 reasoning + f10 normalized；10 库实测 100% 守恒、267/267 行按 step_index 1:1、合计与 transcript 精确相等）。逐调用守恒校验通过时用原生拆分替代字符估算，其余情况回退原字符路径。缓存 v4 → v5。
- **MiniMax Code：调用级 reasoning 拆分。** FIFO 时长配对（已 100% 配对）顺带携带每条消息的 `thinking_content` / `msg_content` 字符，配对调用按自身字符比拆分，取代日级大锅饭；daily 按调用级结果求和 + 未配对残余按日级比例（整天无配对回退旧行为）。缓存 v18 → v19。

### 修复

- MiniMax 时长查询对「坏 `data_json` + 非空 turn_id」行不再抛错（与其他查询一致套 `json_valid`）。
