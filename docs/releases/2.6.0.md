# LLM Monitor 2.6.0

[English](#english) · [简体中文](#简体中文)

## English

### Fixed

- **ZCode「明细采样已达上限」no longer permanently lit.** Root cause: 2.5.5 unified the GLM card's reasoning split but kept two granularities — day-level char split for daily buckets vs row-level split for samples. Totals agreed, but the projection's `includingCurrentDay` merges the authoritative daily bucket with today's sample aggregation **per-bucket with max()**, picking the larger output from one side and the larger reasoning from the other — inflating today's Output+Reasoning (+32,742 tokens measured) so the section's sample sum never matched the daily total.
- Fix: daily `output`/`reasoning` buckets now derive directly from the row-level split sums (same samples, strictly same source) for both the GLM main card and the non-zhipu slices; the day-level char queries (`queryReasoningChars` / `querySliceReasoningChars`) are deleted. `input`/`cacheRead`/`rounds`/`turns` stay SQL-side (split-invariant); conservation unchanged; `includingCurrentDay`'s max() semantics untouched — an exact no-op when the sources agree, still a safety net for genuinely truncated sources. Cache v13 → v14.

## 简体中文

### 修复

- **ZCode 的「明细采样已达上限」不再常亮。** 根因：2.5.5 统一 GLM 卡字符分摊时保留了两套粒度——日聚合走日级字符分摊、样本走行级分摊。总量一致，但投影内核 `includingCurrentDay` 把权威日桶与样本日聚合**逐桶 max()** 合并，从两边各挑大的（实测今日 Output+Reasoning 凭空膨胀 +32,742），导致段的样本合计永远对不上日总量。
- 修法：GLM 主卡与非智谱分片的日桶 `output`/`reasoning` 改为**直接取行级分摊的按日累计**（与样本严格同源）；日级字符查询（`queryReasoningChars` / `querySliceReasoningChars`）删除。`input`/`cacheRead`/`rounds`/`turns` 为拆分不变量维持 SQL 原值；守恒不变；`includingCurrentDay` 的 max() 语义不动——数据一致时是精确 no-op，对真实截断的来源仍是安全网。缓存 v13 → v14。
