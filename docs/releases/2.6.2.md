# LLM Monitor 2.6.2

[English](#english) · [简体中文](#简体中文)

## English

### Fixed

- **Antigravity / agy TTFT retracted — `gen_metadata f1.f11` is the whole call duration, not time-to-first-token.** Full re-inspection (201 gen rows decoded field-by-field) showed `f11` occupies 97–100% of `f11 + f12` (P50 99%) with `f12` at 0.01–0.18s — physically impossible as a streaming window (590 tokens in 0.18s). The original research only ever validated `f11 + f12 ≈ steps duration`, never f11 alone. With the bogus TTFT, the decode-speed denominator collapsed toward zero and inflated the Antigravity speed reading to 432 tok/s (true ≈ 78). The f11 consumption is removed for both harnesses (samples carry nil → UI shows `—`, decode speed uses full duration); the correct f4 native token split is untouched. Caches v10 → v11 (Antigravity) and v5 → v6 (agy) rebuild away the bogus values.

### Changed

- **Harness list column order: TTFT now precedes Speed** — `Turns · Token · Hit · Think · TTFT · Speed · Value · Update`. The seven-day history picker already had TTFT before 速度, so the two surfaces are now consistent.

## 简体中文

### 修复

- **Antigravity / agy 的 TTFT 回退——`gen_metadata f1.f11` 实为整段调用时长，不是首字延迟。** 全量复核（单会话 201 gen 行逐字段解码）显示 `f11` 占 `f11 + f12` 的 97~100%（P50 99%），`f12` 仅 0.01~0.18s——作为流式时长物理不成立（590 tok / 0.18s = 3,278 tok/s）。初版调研只验证过「`f11 + f12` ≈ steps 时长」，从未独立验证 f11 本身。伪 TTFT 使解码速度分母 ≈0，把 Antigravity 速度撑到 432 tok/s（真实约 78）。两个 harness 的 f11 消费已移除（样本恒 nil → UI 显示 `—`，解码速度按时长全额计入）；正确的 f4 原生 token 拆分不受影响。缓存 v10 → v11（Antigravity）、v5 → v6（agy）重建清除伪值。

### 变更

- **Harness 列表列序：TTFT 移到 Speed 之前** —— `Turns · Token · Hit · Think · TTFT · Speed · Value · Update`。7 天历史 picker 此前已是 TTFT 在 速度 之前，两处口径一致。
