# LLM Monitor 2.7.1

## English

### Fixed

- Align OpenCode and MiniMax reasoning splits across samples and daily totals; exclude Agy tool calls from fallback durations and detect conversation database updates. Rebuild affected local caches.
- Reject overflowing MiniMax/GLM quota values. Bound DSH decompression output while it is produced and stop fallback decoding after a size-limit failure.
- Recover configuration files recreated between watcher retries, settle startup after providers are disabled, clear canceled quota loading states, and preserve Fleet totals until local sources have produced a verified result.
- Recheck Bark cooldowns when queued notifications are dispatched. Restore menu reopen timers, settings navigation, stable Dock selection after reordering, and menu quota-source controls.
- Keep holiday draft refreshes separate from committed-source detection and prevent late responses from replacing a newly selected source.
- Support release builds from fresh checkouts without a local build counter; correct analysis-script cumulative totals and empty/zero-data handling; update persistence and performance documentation.

## 简体中文

### 修复

- 统一 OpenCode、MiniMax 样本与日桶的推理分拆；Agy 工具样本不再误补耗时，conversation 数据库单独变更也会重扫。相关本地缓存升级重建。
- 拦截 MiniMax/GLM 额度极值造成的整数崩溃；DSH 在解压过程中执行输出体积上限，超限后不再重复尝试解码。
- 配置文件在监听重试间隙重建后可正确载入；启动途中停用 Provider 后正常结算；取消的额度请求退出转圈；本地来源首次验证完成前保留 Fleet 已存用量。
- Bark 排队发送时重新检查冷却；修复菜单重开计时、设置导航、Dock 重排后的选择，以及菜单额度来源按钮。
- 节假日草稿刷新与已保存源分离，旧源响应不能覆盖新源的表、缓存或刷新状态。
- 新检出仓库无构建号文件也能执行发布入口；分析脚本修正累计口径并支持空/零数据；校正持久化和性能文档。
