# LLM Monitor 2.7.2

## English

### Fixed

- Correct MiniMax reasoning allocation when native, paired and fallback samples occur on the same day; rebuild affected caches.
- Apply local-scan generation checks and results in one main-actor transaction. Stop queued configuration events and canceled requests from restarting stopped services or applying stale results.
- Keep subprocess timeout and cancellation active while waiting for inherited output pipes after the parent exits.
- Revalidate holiday caches on source switches; missing, corrupt, empty or unsuccessfully written caches no longer suppress refreshing.
- Preserve explicit-build counter immutability. Exclude later usage records from earlier rate-limit totals, including records belonging to the same call. Correct persistence-path documentation.
- Serialize notification-state writes through shutdown and allow retries after failed writes. Restore verified same-generation Fleet snapshots after restart and propagate cancellation to Antigravity authentication subprocesses.
- Keep Codex scan ownership across cancellation and restart. Preserve fractional seconds in local caches and rebuild older caches to keep cold and warm quota-window accounting consistent.
- Name Settings controls for accessibility and keep expanded usage history within narrow windows. Refresh all supported offline log formats with private file permissions, correct duplicated token accounting, and remove unrelated historical conclusions.

## 简体中文

### 修复

- 修正 MiniMax 同日原生、配对与回退样本混用时的推理残余分配，并重建相关缓存。
- 本地扫描代际校验与结果应用在一次主线程事务内完成；已停止应用不再被排队配置事件或取消后返回的旧请求恢复服务、覆盖状态。
- 子进程退出后等待继承管道时仍执行超时/取消检查，避免流程无限等待。
- 节假日源切换时重新核对缓存，写入失败、缺失、损坏或空表不再阻断刷新。
- 显式构建号不创建本地计数文件；限流累计排除同一调用较晚出现的用量；校正持久化路径文档。
- 修复通知旧写覆盖停机新基线及写失败后无法重试、Fleet 重启后同代有效快照不展示、Antigravity 认证子进程取消断链。
- Codex 扫描取消/重启按 owner 隔离；本地缓存保存小数秒并重建旧缓存，保持冷、暖扫描的额度窗口归属一致。
- 设置控件补齐可访问性名称，展开历史在窄窗口内滚动；离线工具覆盖全部文本格式、刷新过期解压结果并保护明文权限，修正重复计量及无关的历史结论。
