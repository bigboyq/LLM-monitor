# LLM Monitor 2.7.6

## English

### Fixed

- Fix ChatGPT API credits (API赠金) used-amount over-counting at the billing-cycle boundary: the OpenAI costs endpoint only supports UTC-day-aligned daily buckets (`start_time` snaps down to UTC midnight), so usage from before the reset anchor (e.g. 15:34 local) leaked into the new cycle's total and stayed there all month.
- Introduce a per-key 「边界扣除 ($)」 (boundary-day deduction): after the snapshot window (anchor +1 h, when credits are cleared and no new usage can accrue) the boundary bucket's spill-over amount is **written into the config field automatically**; an estimated deduction (window missed) is marked with an orange indicator on the card row. Automatic and manual values share the same config field — once fixed within a cycle (whether auto-written or manually edited), automatic correction stops until the next cycle.
- The used-amount formula simplifies to `max(0, daily-bucket total − boundary deduction)`; the deduction is manually editable in Settings (negatives allowed), covering estimate drift and partial first-month quotas.

## 简体中文

### 修复

- 修复 ChatGPT API 赠金「已用金额」在账期边界多算的问题：OpenAI costs 接口只支持按 UTC 整日对齐的日桶（`start_time` 会被向下吸附到 UTC 0 点），重置锚点（如本地 15:34）之前的上一周期用量整桶漏入新周期，且整个周期一直挂在「已用」上。
- 引入按 Key 的「边界扣除 ($)」：快照窗口（锚点 +1 小时，期间赠金清零、无新增用量）结束后的边界桶溢入额**自动写入配置项**，估算（错过窗口）时卡片明细行以橙色图标标注；自动与手动共享同一配置值——周期内一旦定值（自动写入或手动修改）自动修正即失效，下期重新采集。
- 已用公式简化为 `max(0, API 日桶合计 − 边界扣除)`，设置页可直接手动定值该扣除（支持负数），覆盖估算偏差与首月不满额度场景。
