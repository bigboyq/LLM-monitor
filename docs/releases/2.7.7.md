# LLM Monitor 2.7.7

## English

### Fixed

- Fix GLM reset cards and activity-plan sections silently disappearing: ZCode client 3.18.0 rewrote `~/.zcode/v2/credentials.json` into the new `enc:v2:` encrypted format, and the previous reader treated the ciphertext blob as a plain JWT, so the two dual-credential zcode.z.ai endpoints (reset cards / activity-plan balance) returned 401 while the unauthenticated marketing endpoint kept returning 200.
- Add `enc:v2:` decryption to `GlmZcodeCredentialReader` (CryptoKit AES-256-GCM): the `os` variant reads its 32-byte key from the macOS Keychain entry `ZCode Credential Encryption` (account = SHA256 of the credentials file path); the `env` variant derives the key from `ZCODE_CREDENTIAL_SECRET` or a sibling `credential-secret` file. Decryption failures degrade to a missing credential with a sanitized warning instead of aborting the credential load; the legacy `enc:v1:` and plaintext paths are unchanged.

## 简体中文

### 修复

- 修复 GLM 重置卡与活动套餐信息静默消失：ZCode 客户端 3.18.0 将 `~/.zcode/v2/credentials.json` 凭证重写为新的 `enc:v2:` 加密格式，旧版 reader 把密文整段当作明文 JWT 发送，导致 zcode.z.ai 双凭证接口（重置卡 / 活动套餐余额）401，而不校验 Authorization 的营销接口仍返回 200（曾造成「JWT 有效」的假象）。
- `GlmZcodeCredentialReader` 新增 `enc:v2:` 解密（CryptoKit AES-256-GCM）：`os` 变体从 macOS 钥匙串条目 `ZCode Credential Encryption`（account = 凭证文件路径的 SHA256）读取 32 字节密钥；`env` 变体由 `ZCODE_CREDENTIAL_SECRET` 或同目录 `credential-secret` 文件派生密钥。解密失败降级为该凭证缺失并记录脱敏警告，不中断其余凭证加载；`enc:v1:` 与明文路径保持不变。
